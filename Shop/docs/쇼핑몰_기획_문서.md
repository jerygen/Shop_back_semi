# 쇼핑몰 개인 프로젝트 기획 문서

## 1. 프로젝트 개요

본 프로젝트는 상품 조회, 주문, 장바구니, 관리자 상품/주문/매출/회원 관리, 고객센터 1:1 실시간 채팅을 제공하는 쇼핑몰 백엔드 시스템이다. 프론트엔드 화면은 개발 범위에서 제외하고, Swagger(OpenAPI 3.0)를 API 검증 및 화면 대용 인터페이스로 활용한다.

## 2. 프로젝트 목표

- 고객은 로그인 후 상품을 장바구니에 담거나 단건 주문을 생성할 수 있다.
- 고객은 본인의 주문 내역과 주문 상세 정보를 조회할 수 있다.
- 관리자는 상품을 등록, 수정, 삭제하고 전체 주문 내역, 상품별 매출 통계, 회원 정보를 확인할 수 있다.
- 고객과 관리자는 WebSocket + STOMP 기반의 1:1 문의 채팅을 사용할 수 있다.
- 상품 전체/상세 조회를 제외한 모든 API는 JWT 인증을 통해 보호한다.

## 3. 개발 범위

### 3.1 포함 범위

- JWT 기반 로그인 및 인증 필터
- 사전 등록된 회원 데이터 기반 로그인
- 상품 전체 조회 및 상세 조회
- 고객 단건 주문, 주문 내역 조회
- 장바구니 담기, 장바구니 조회, 장바구니 일괄 주문
- 관리자 상품 CRUD
- 관리자 전체 주문 조회, 상품별 판매량/매출 통계, 회원 조회
- 고객센터 채팅방 생성/입장, 관리자 채팅방 목록 조회/입장
- 채팅 메시지 실시간 송수신, 저장, 과거 내역 조회
- Swagger UI 기반 API 테스트 환경

### 3.2 제외 범위

- 회원가입 화면 및 회원가입 API
- 별도 프론트엔드 화면
- 결제 연동
- 배송사 연동
- 쿠폰, 포인트, 리뷰, 찜하기 등 부가 커머스 기능

## 4. 사용자 및 권한

| 사용자 유형 | 설명 | 주요 기능 |
|---|---|---|
| 비회원 | 인증 없이 접근하는 사용자 | 상품 전체 조회, 상품 상세 조회, 로그인 |
| 일반 고객 | ROLE_USER 권한 사용자 | 주문, 장바구니, 주문 내역, 고객센터 문의 |
| 관리자 | ROLE_ADMIN 권한 사용자 | 상품 관리, 전체 주문 조회, 매출 관리, 회원 관리, 고객센터 응대 |
| 시스템 | 서버 내부 처리 주체 | 채팅 메시지 저장, 주문 금액 계산, 재고 차감 |

## 5. 핵심 업무 흐름

### 5.1 로그인

1. 사용자가 아이디와 비밀번호를 제출한다.
2. 서버가 사전 등록된 회원 정보를 기준으로 인증한다.
3. 인증 성공 시 JWT 토큰을 발급하고 응답 헤더와 사용자 기본 정보를 반환한다.
4. 이후 보호 API 요청은 `Authorization: Bearer {token}` 헤더를 사용한다.

### 5.2 상품 조회

1. 누구나 상품 목록을 조회할 수 있다.
2. 누구나 상품 번호를 기준으로 상품 상세 정보를 조회할 수 있다.
3. 상품 데이터에는 상품 번호, 상품 ID, 상품명, 가격, 재고, 설명, 등록일이 포함된다.

### 5.3 단건 주문

1. 고객이 상품 번호, 수량, 배송지를 입력한다.
2. 서버가 상품 존재 여부와 재고를 검증한다.
3. 주문과 주문 상세를 생성한다.
4. 주문 금액을 계산하고 상품 재고를 차감한다.
5. 생성된 주문 정보를 반환한다.

### 5.4 장바구니 주문

1. 고객이 상품 번호와 수량을 장바구니에 담는다.
2. 같은 상품이 이미 장바구니에 있으면 수량을 합산한다.
3. 고객은 본인의 장바구니 목록을 조회한다.
4. 장바구니 전체 주문 시 각 상품의 재고를 검증한다.
5. 주문과 주문 상세를 생성한 뒤 장바구니를 비운다.

### 5.5 관리자 운영

1. 관리자는 상품을 등록, 수정, 삭제한다.
2. 관리자는 모든 고객의 주문 내역과 주문 상세를 조회한다.
3. 관리자는 상품별 판매량과 매출 합계를 확인한다.
4. 관리자는 회원 기본 정보와 누적 주문 수를 조회한다.

### 5.6 고객센터 채팅

1. 고객이 관리자에게 문의할 채팅방을 생성하고 입장한다.
2. 관리자는 개설된 채팅방 목록을 확인하고 특정 방에 입장한다.
3. 참여자는 WebSocket + STOMP로 실시간 메시지를 주고받는다.
4. 메시지는 DB에 시간순으로 저장된다.
5. 채팅방 입장 시 이전 메시지 내역을 조회한다.

## 8. 비기능 요구사항

- 보안 및 인증: 상품 전체/상세 조회를 제외한 모든 API 요청은 JWT 인증을 요구한다.
- 권한 제어: 고객 기능은 ROLE_USER, 관리자 기능은 ROLE_ADMIN 기준으로 접근을 제한한다.
- 인터페이스: Swagger(OpenAPI 3.0)를 API 문서 및 테스트 화면으로 활용한다.
- 아키텍처: 일반 기능은 HTTP REST API, 채팅 기능은 WebSocket + STOMP를 사용한다.
- 데이터 정합성: 주문 생성 시 주문 금액, 주문 상세 금액, 재고 차감이 하나의 트랜잭션으로 처리되어야 한다.
- 예외 처리: 인증 실패, 권한 없음, 상품 없음, 재고 부족, 장바구니 비어 있음 등 주요 실패 케이스를 표준 응답으로 반환한다.

## 9. 성공 기준

- Swagger에서 로그인 후 JWT를 사용해 보호 API를 호출할 수 있다.
- 비회원은 상품 조회만 가능하고 주문/장바구니/관리자/채팅 API 접근은 거부된다.
- 고객은 단건 주문과 장바구니 주문을 정상 생성할 수 있다.
- 주문 생성 시 재고와 금액이 정확히 반영된다.
- 관리자는 상품 관리, 전체 주문 조회, 매출 통계, 회원 조회를 수행할 수 있다.
- 고객과 관리자는 동일 채팅방에서 메시지를 실시간 송수신하고, 재입장 시 이전 메시지를 확인할 수 있다.
